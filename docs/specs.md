# rachite 仕様

## 概要

rachite は、traP のチャットサービス traQ で動く旧 Bot（`test2`）を作り直し、検出した川柳とコマンドの使い方を部内向け Web で閲覧できるようにするプロジェクトです。

## 構成

| 構成       | 役割                                                                                                                          |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `apps/web` | React、TypeScript、Vite、MUI。川柳一覧とコマンドの使い方を表示します。                                                        |
| `apps/api` | Rust、Axum、Tokio。Web 向け HTTP API、traQ Bot、スタンプ送信ワーカーを同じバックエンドプロセスで実行します。                  |
| MariaDB    | チャンネルごとの川柳検出設定と検出結果を永続化します。SQLx で接続し、マイグレーションは `apps/api/migrations/` で管理します。 |

Bot は traQ の WebSocket からイベントを受信し、返信やスタンプ送信には traQ の HTTP API を使います。初版では本番 Bot の受信を有効にしたバックエンドを1インスタンスで稼働させます。

Web と Web 向け API は同一オリジンで提供し、両方を Hard 認証の配下に置きます。閲覧対象は部員です。川柳一覧に掲載するチャンネルの個別指定は設けません。

Web は HeroUI の Default テーマを参考に、ライト／ダークともに中立色の背景と `#0485F7` のアクセントを使います。ナビゲーションでは現在のページを示し、読み込み・エラー・データなしを区別して表示します。

## Bot コマンド

旧 Bot のメンション単体への応答と、旧コマンドの名前・引数・ガチャの抽選条件を引き継ぎます。

| 入力                                                     | 挙動                                                                                     |
| -------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `@BOT_lachite`                                           | 呼びかけたユーザーにメンションを返します。                                               |
| `ping [文字列]`                                          | 呼びかけたユーザーに pong と経過時間を返します。任意の引数も旧版と同様に返信に含めます。 |
| `join` / `leave`                                         | コマンドを受け取ったチャンネルに Bot が参加・退出します。                                |
| `lachitegacha` / `n3gacha`                               | 名前がそれぞれ `lachite` / `n3` で始まるスタンプから1つ抽選します。                      |
| `stampgacha <search>`                                    | 名前に指定語を含むスタンプから1つ抽選します。大文字・小文字を区別しません。              |
| `stampgacha /pattern/flags`                              | 名前が ECMAScript の正規表現に一致するスタンプから1つ抽選します。                        |
| `stampbomb <stamp> <number> <message-link>`              | 指定したスタンプを対象メッセージに押す処理を受け付けます。                               |
| `senryu status` / `senryu on` / `senryu off`             | 誰でもコマンドを送ったチャンネルの川柳検出状態を表示・変更できます。                     |
| `mogamigawa status` / `mogamigawa on` / `mogamigawa off` | 誰でもコマンドを送ったチャンネルの最上川の状態を表示・変更できます。                     |

コマンドは Bot 宛てメンションの後に指定します。コマンドの名称・書式・説明は、Bot のヘルプと Web の使い方ページで共通の定義を参照します。

### スタンプガチャ

- `stampgacha` はコマンドに続く最初の1語を検索に使います。通常の文字列は名前との部分一致です。引数が空なら使い方を返します。
- `/pattern/flags` のパターンとフラグは ECMAScript の `RegExp` に従います。`/foo` のように閉じるスラッシュがない場合は通常の文字列として検索します。`/foo/bar` は `bar` が無効なフラグなので入力エラーです。`/foo\/bar/` や `/[/]/` で名前のスラッシュに一致させられます。
- 正規表現は既定で大文字・小文字を区別しません。`/N3/` と `/N3/i` は同じ挙動です。区別するには `/(?-i:^N3)/` のように式の中で `i` を解除します。`g` や `y` を使う場合もスタンプ名ごとに照合位置を先頭へ戻します。
- たとえば `@BOT_lachite stampgacha /^(lachite|n3)/` は、名前が `lachite` または `n3` で始まるスタンプから抽選します。式に半角スペースを含めたい場合は `/foo\x20bar/` と書けます。
- `//` や無効な式・フラグは入力エラーです。全件を対象にするには `/.*/` を使います。有効な式に一致する候補がゼロの場合は候補なしと返します。時間切れの場合はその旨を返し、全候補の照合が完了した場合に抽選します。

### スタンプ送信

- `stampbomb` の指定回数は旧版と同じ1〜10,000回です。traQ API への送信は1リクエストあたり最大100スタンプに分けます。
- 単一ワーカーが容量に上限のあるキューを処理し、ジョブの境目を含めて、スタンプ送信用 HTTP リクエストの開始間隔を最低50 ms空けます。目安は毎秒20リクエストです。
- キューが満杯のときは「混雑中」と返します。結果が不明なタイムアウトでは該当分の自動再送を避け、途中終了を通知します。

## 川柳の検出と掲載

- 川柳は、投稿の途中も含めて、文節の境界で区切れる最初の 5・7・5 拍を探します。本文抽出と拍数計算は最上川と共用します。
- Bot が受信した通常のチャンネル投稿を対象とします。投稿者が Bot の場合は処理対象から外します。チャンネル設定が未登録の場合は、検出をオンとして扱います。
- 検出がオンのチャンネルで新規投稿から句を検出したら、MariaDB に保存し、traQ のチャンネルにも従来どおり検出を通知します。
- 元投稿が編集されたら、編集後の本文を再判定します。掲載済みの句は、引き続き検出できれば更新し、検出できなくなれば取り下げます。未掲載の投稿から編集によって初めて句を検出した場合は、検出がオンなら一覧に追加します。編集に伴う更新は Web 一覧だけに反映します。
- 元投稿が削除されたら、対応する句を一覧から取り下げます。
- 検出をオフにすると、そのチャンネルで新しく句を登録する処理を止めます。掲載済みの句は残り、元投稿の編集・削除は引き続き反映します。オンに戻した時点から新規登録を再開します。
- 初版は Bot が受信したイベントを反映します。停止・切断中の編集や削除をさかのぼって照合する仕組みは今後の検討事項です。

### 川柳と最上川の本文抽出・拍数

- traQ イベントの `text` から、強調・見出し・箇条書き・引用ブロック・表の文章とリンクの表示ラベルを取り出します。装飾記号・箇条書きの番号・区切り線・URL・添付やメッセージの埋め込み・コード・数式・ネタバレ・スタンプ・メンションは拍に含めません。ユーザーが `[引用メッセージ]` と入力した場合は本文として扱います。
- 空白・改行・空行・区切り線・リスト項目の境目をまたいで句を探します。構造の境目は前後の語が連結しないよう空白として扱います。語の途中の強調などは外側の文字とつなげます。
- Lindera と SudachiDict で読みを取ります。かなだけの語は表記からも数えられます。漢字・英字・数字を含む語は、かなの読みが取れた場合に数えます。英字だけで構成された句も、読みと文節が条件を満たせば対象です。単独の記号や絵文字は拍に含めず、長音符 `ー`、促音 `っ`、撥音 `ん` は1拍です。
- 読み不明の語に当たると、川柳はその語を含む候補を打ち切り、後ろから探索を再開します。最上川は、本文に読み不明の語があれば反応しません。`古池や zzzzz 蛙飛びこむ` の `zzzzz` が読み不明なら、最上川にはなりません。
- 辞書切り替え時点の掲載内容はそのまま残し、元投稿の編集時に新しい辞書で再判定します。元投稿の削除時は一覧から取り下げます。解析処理が失敗した場合は掲載状態を保持します。

## 最上川

- 人による通常のチャンネル投稿を、新規投稿時に判定します。Bot の投稿と Bot 宛てのコマンドは対象外です。
- 川柳と同じ方法で抽出した本文の全体が、文節の境界でちょうど 5・7 拍に分かれる場合に反応します。たとえば「古池や 蛙飛びこむ」は該当し、「古池や 蛙飛びこむ 水の音」の全体は 5・7・5 拍です。
- チャンネル設定が未登録の場合は有効です。`mogamigawa on` / `off` の切り替えは、コマンドを送ったチャンネルの以後の新規投稿に適用します。川柳検出の設定とは独立です。
- 検出した句を、5・7 に「最上川」を添えた3行で保存します。対象のスタンプ3種を名前の完全一致で特定したら、元投稿 ID で重複実行を防ぎ、同じチャンネルに次の2行を投稿します。

  ```text
  最上川
  <元の投稿のリンク>
  ```

- 投稿が成功したら、元投稿に `mogamigawa01_mo`、`mogamigawa02_gami`、`mogamigawa03_gawa` をこの順に1個ずつ付けます。同じスタンプが既に押されている場合も1個追加します。順序は Bot が API を呼ぶ順です。
- スタンプ3種が揃わなければ、ログに記録して処理を終えます。投稿やスタンプ送信が途中で失敗した場合は、元投稿 ID と失敗箇所をログに残して処理を打ち切り、成功済みの操作はそのまま残します。結果が不明なタイムアウトも自動では再送しません。
- 一覧に掲載中の元投稿が編集されたら、引き続き 5・7 なら句を更新し、条件を外れたら取り下げます。元投稿が削除された場合も取り下げます。編集・削除による変更は一覧だけに反映し、返信・スタンプは新規投稿時に送ります。

## 保存するデータと Web の表示

| データ           | 保存内容                                                                                                                                 |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| チャンネル設定   | traQ のチャンネル ID、川柳検出と最上川それぞれの有効状態、更新日時。                                                                     |
| 川柳の検出結果   | 抽出した句、元メッセージ ID、チャンネル ID、検出日時。元メッセージ ID を一意にします。                                                   |
| 最上川の検出結果 | 句、元メッセージ ID、チャンネル ID、検出日時、掲載状態、返信処理の開始状態。元メッセージ ID を一意にして返信・スタンプの重複を防ぎます。 |

元投稿へのリンクはメッセージ ID から組み立てます。チャンネル名、投稿者の表示名、アイコンといった traQ の表示用情報は、必要になった段階で取得します。川柳一覧は `/senryu`、最上川一覧は `/mogamigawa` で、句と検出日時、元投稿へのリンクを新着順に一定件数ずつ表示します。元メッセージ ID のみ保存されていた最上川は、一覧の末尾で元投稿へのリンクを表示します。コマンドの使い方は `/commands` に掲載します。`/` は共通ナビゲーションのみ表示し、今後のトップページ用に予約します。

追加コマンドの内容と LLM の用途は、各機能の着手時に決めます。
