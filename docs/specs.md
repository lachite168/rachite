# rachite 機能仕様

## 提供範囲

rachite は traQ の旧 Bot（`test2`）を引き継ぎ、川柳・最上川の検出結果と Bot の使い方を部内向け Web に掲載します。Web、API、Swagger UI は同じオリジンで提供し、公開環境では Hard 認証を適用します。検出結果には掲載チャンネルの個別指定を設けません。 [公開環境の設定](NEOSHOWCASE.md#urls)

## Bot コマンド

チャンネルでは Bot 宛てメンションの後にコマンドを指定します。Bot との DM では `markov` を同じ書式で使えます。コマンドの使い方は Bot の `help` と Web の `/commands` に表示します。 [コマンド定義](../apps/api/src/bot/commands.rs)

| 入力                                                     | 挙動                                                                  |
| -------------------------------------------------------- | --------------------------------------------------------------------- |
| `@BOT_lachite`                                           | 呼びかけたユーザーにメンションを返す                                  |
| `help`                                                   | コマンドの使い方を返す                                                |
| `ping [文字列]`                                          | pong と経過時間を返す。最初の引数があれば返信に含める                 |
| `join` / `leave`                                         | 実行したチャンネルに参加・退出する                                    |
| `lachitegacha` / `n3gacha`                               | 名前がそれぞれ `lachite` / `n3` で始まるスタンプからランダムに1つ選ぶ |
| `stampgacha <search>` / `stampgacha /pattern/[flags]`    | 名前が検索条件に一致したスタンプからランダムに1つ選ぶ                 |
| `stampbomb <stamp> <number> <message-link>`              | 対象メッセージへのスタンプ送信を受け付ける                            |
| `senryu status` / `senryu on` / `senryu off`             | 実行したチャンネルの川柳検出の状態を表示・変更する                    |
| `mogamigawa status` / `mogamigawa on` / `mogamigawa off` | 実行したチャンネルの最上川検出の状態を表示・変更する                  |
| `markov <username> [n] [--here]`                         | 指定ユーザーの発言から文章を1件生成する                               |

### スタンプガチャ

- `stampgacha` は最初の引数を検索に使います。通常の文字列はスタンプ名との部分一致です。引数がなければ使い方を返します。
- `/pattern/[flags]` は ECMAScript の正規表現です。`/foo` のように閉じるスラッシュがなければ通常の文字列として検索します。`/foo/bar` は `bar` が無効なフラグなので入力エラーです。名前のスラッシュは `/foo\/bar/` や `/[/]/` で照合できます。
- 通常の検索と正規表現は大文字・小文字を区別しません。正規表現で区別するには `/(?-i:^N3)/` のように式の中で `i` を解除します。照合位置は `g` や `y` を指定した場合もスタンプ名ごとに先頭へ戻します。
- `/^(lachite|n3)/` で両方の接頭辞を検索できます。正規表現に半角スペースを含める場合は `/foo\x20bar/` のように書きます。
- `//` や無効な式・フラグは入力エラーです。全件を対象にするには `/.*/` を使います。一致がゼロなら候補なしと返します。全候補の照合が完了した場合に抽選し、時間切れの場合はその旨を返します。

### スタンプ送信

- `stampbomb` の指定回数は1〜100,000回です。traQ API への送信は1リクエストあたり最大100スタンプに分けます。
- 単一ワーカーが容量制限付きのキューを処理します。HTTP リクエストの開始間隔はジョブの境目も含めて最低50 msです。キューが満杯なら混雑中と返します。
- 送信に失敗した場合は、確認できた回数を添えて途中終了を通知します。結果不明のタイムアウトも自動再送せずに終了します。

### マルコフ生成

誰でも `markov <username> [n] [--here]` を使えます。アカウント名は大文字・小文字を区別せず照合し、先頭の `@` は省略できます。`n` は直前に参照する形態素の数で、1〜4の整数、既定は2です。`--here` は末尾に置きます。

| 実行場所    | 既定の検索範囲     | `--here` の検索範囲                                           |
| ----------- | ------------------ | ------------------------------------------------------------- |
| チャンネル  | 公開チャンネル全体 | 実行したチャンネル。非公開チャンネルでは Bot の閲覧権限が必要 |
| Bot との DM | 公開チャンネル全体 | 実行者と Bot の DM                                            |

- 実行時に、投稿日時の新しい順に最大300件取得します。DM の `--here` では該当の DM 履歴を最大300件取得してから投稿者を絞ります。本文とモデルは実行中のメモリ上で扱います。
- [共通の本文抽出](#川柳と最上川の本文抽出拍数)と辞書を使います。マルコフ生成では引用ブロックの中身を除き、Bot 宛てコマンドと抽出後に空の投稿を素材から外します。
- 投稿ごとに開始・終了を記録し、直前の `n` 形態素に続く候補を出現頻度に応じて抽選します。候補が前処理後の元投稿と全文一致した場合や、100形態素または500文字を超えた場合は引き直します。
- 生成に成功すると、traQ の自動埋め込みを無効にして、実行した場所に生成文だけを1件返信します。素材がなければその旨を返し、指定の階数で新しい文を得られなければ階数を下げる案内を返します。容量制限付きのワーカーに処理を渡し、キューが満杯なら混雑中と返します。

## 川柳の検出と掲載

- 川柳と最上川は、人が書いた通常のチャンネル投稿を対象にします。Bot 宛てコマンドは対象外です。チャンネルごとに設定を持ち、どちらも設定がなければオンです。チャンネルに投稿できる人なら誰でも状態の確認と切り替えができます。
- 川柳は投稿の途中も含めて、文節の境界で区切れる最初の5・7・5拍を探します。有効なチャンネルで新規投稿から句を検出すると、保存して同じチャンネルに通知します。
- 編集後も条件を満たせば掲載済みの句を更新し、条件を外れれば取り下げます。未掲載の投稿が編集によって条件を満たした場合、川柳検出がオンなら一覧に追加します。編集による反映は Web 一覧のみです。
- 元投稿が削除されたら一覧から取り下げます。検出をオフにしても掲載済みの句は編集・削除を反映します。新規登録はオンに戻すと再開します。
- 編集・削除は Bot が受信したイベントを反映します。Bot の停止・切断中の変更は自動で照合しません。

## 最上川

- 本文全体が文節の境界でちょうど5・7拍に分かれるときに検出します。「古池や 蛙飛びこむ」は該当します。「古池や 蛙飛びこむ 水の音」の全体は5・7・5拍です。
- 川柳検出とは別にチャンネルごとに切り替えられます。設定変更は以後の新規投稿に適用します。
- 検出した5・7に「最上川」を添えた3行を保存します。対象のスタンプ3種を名前の完全一致で特定したら、元投稿 ID で重複実行を防ぎ、同じチャンネルに次の2行を投稿します。

  ```text
  最上川
  <元の投稿のリンク>
  ```

- 投稿が成功したら、元投稿に `mogamigawa01_mo`、`mogamigawa02_gami`、`mogamigawa03_gawa` を順に1個ずつ付けます。先に押されているスタンプも1個追加します。順序は Bot の API 呼び出し順です。
- 必要なスタンプが見つからない場合や、投稿・送信が失敗した場合は元投稿 ID と失敗箇所を記録して処理を終えます。途中で失敗した場合、成功済みの操作は保持します。結果不明のタイムアウトも自動再送せずに終了します。
- 掲載中の投稿の編集で引き続き5・7なら句を更新し、条件を外れた場合や削除された場合は取り下げます。編集・削除の反映は Web 一覧のみです。

## 川柳と最上川の本文抽出・拍数

- 元の本文から、強調・見出し・箇条書き・表の文章とリンクの表示ラベルを取り出します。装飾記号、箇条書きの番号、区切り線、URL、添付やメッセージの埋め込み、コード、数式、スポイラー、スタンプ、メンションを除きます。
- 川柳・最上川では引用ブロックの文章を使います。ユーザーが文字通り `[引用メッセージ]` と入力した場合も本文として扱います。
- 空白・改行・空行・区切り線・リスト項目の境目をまたいで句を探します。構造の境目では前後の語が連結しないよう空白を入れ、語の途中にある強調では外側の文字とつなげます。
- Lindera と SudachiDict で読みを取ります。かなだけの語は表記からも数えられます。漢字・英字・数字を含む語は、かなの読みが取れた場合に数えます。英字だけでも読みと文節が条件を満たせば対象です。単独の記号や絵文字は0拍、長音符 `ー`、促音 `っ`、撥音 `ん` は各1拍です。
- 読み不明の語がある場合、川柳はその語を含む候補を打ち切り、後ろから探索を再開します。最上川は判定を見送ります。たとえば「古池や zzzzz 蛙飛びこむ」で `zzzzz` の読みが不明なら最上川になりません。
- 辞書を切り替えても掲載済みの結果を維持し、元投稿の編集時に新しい辞書で再判定します。解析処理が失敗した場合は掲載状態を保持します。

## 保存するデータと Web の表示

| データ           | 保存内容                                                                                           |
| ---------------- | -------------------------------------------------------------------------------------------------- |
| チャンネル設定   | traQ のチャンネル ID、川柳と最上川それぞれの有効状態、更新日時                                     |
| 川柳の検出結果   | 句、元メッセージ ID、チャンネル ID、検出日時。元メッセージ ID は一意                               |
| 最上川の検出結果 | 句、元メッセージ ID、チャンネル ID、検出日時、掲載状態、返信処理の開始状態。元メッセージ ID は一意 |

| Web の URL    | 表示内容                               |
| ------------- | -------------------------------------- |
| `/`           | 共通ナビゲーション                     |
| `/senryu`     | 川柳の句、検出日時、元投稿へのリンク   |
| `/mogamigawa` | 最上川の句、検出日時、元投稿へのリンク |
| `/commands`   | Bot コマンドの使い方                   |

検出結果は新着順に20件ずつ取得します。最上川の旧形式の記録は一覧の末尾に元投稿へのリンクを表示します。ライト・ダークともに中立色の背景と `#0485F7` を使い、読み込み、エラー、データなしを画面で区別します。 [配色の参考](https://heroui.com/en/themes)・[画面設計の参考](https://www.uxpin.com/studio/jp/blog-jp/ui-design-principles-ja/)
