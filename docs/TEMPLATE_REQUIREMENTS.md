# フルスタック Web アプリひな形の要件

Rust と React を使う新規プロジェクトで、画面・API・データベースをすぐにつなぎ、開発を始められるようにする。今回の技術構成と、別のプロジェクトでも満たしたい条件を記録する。バージョンは今回の採用例であり、再利用時は互換性に合わせて選び直してよい。

## 1. リポジトリ構成

- 1つのモノレポに `apps/web`（React）と `apps/api`（Rust）を置く。ルートに npm workspaces の `package.json` と Cargo workspace の `Cargo.toml` を置く。
- 依存関係の解決結果を `package-lock.json` と `Cargo.lock` に記録し、CI とコンテナのビルドにも使う。
- Web は画面、共通コンポーネント、API クライアント、状態管理を分ける。API はルーティング・認証・アイテム・エラー処理を分け、SQL マイグレーションと統合テストを同じクレート内で管理する。
- 環境変数の例を `.env.example` に置く。実際の `.env`、SQLite のデータファイル、依存関係のインストール先、ビルド成果物は Git の管理対象外とする。

## 2. 技術構成

| 領域             | 今回の採用例と役割                                                                                                          |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Web 基盤         | React 19、TypeScript 7、Vite 8。Node.js 26.13.1（`.node-version` で指定）。`@/*` で `apps/web/src/*` を参照できるようにする |
| UI               | Material UI 9、MUI Icons、Emotion。notistack 3 で操作結果を通知する                                                         |
| 状態と画面遷移   | TanStack Query 5 でサーバー状態と再取得を管理。Zustand 5 でテーマとセッションを管理。React Router 7 で画面を切り替える      |
| 日時             | API は chrono で ISO 8601 形式の日時を返し、Web は dayjs で日本語の日時・相対日時を表示する                                 |
| API              | Rust stable（edition 2024）、Axum 0.8、Tokio 1、Serde。tower-http 0.7 で CORS と HTTP トレース、tracing でログを扱う        |
| 設定とエラー     | dotenvy でローカル設定を読み込む。thiserror で API エラー、anyhow で起動時や内部のエラーを扱う                              |
| DB               | SQLite と SQLx 0.9。起動時に DB ファイルを作成し、SQL マイグレーションを適用する。ID は UUID v7                             |
| 認証             | Argon2id でパスワードをハッシュ化し、jsonwebtoken 12 で有効期限付きの JWT を発行・検証する                                  |
| API ドキュメント | utoipa 6 と utoipa-swagger-ui 10。OpenAPI JSON とブラウザで試せる Swagger UI を用意する                                     |
| 外部 HTTP 通信   | reqwest 0.13。外部 API を追加するときに使える共有クライアントを、タイムアウト付きで用意する                                 |

## 3. ひな形で動くサンプル

- メールアドレスとパスワードでアカウントを登録し、ログイン・ログアウトできる。初期アカウントは設けず、最初のユーザーは画面から登録する。
- ログイン後に自分のアイテムを一覧・作成・閲覧・編集・削除できる。アイテムにはタイトル、説明、完了状態、作成日時、更新日時を持たせる。一覧では完了状態で絞り込める。
- `/` はログイン前の登録・ログイン画面とログイン後の一覧を兼ねる。`/items/:id` は詳細・編集、`/about` はアプリの説明を表示する。
- 操作の結果や入力エラーを画面に表示する。ライト／ダークテーマの設定はブラウザに保存する。
- アイテムの操作には Bearer トークンを要求する。DB クエリは所有者で絞り込み、別ユーザーのアイテムには `404` を返す。
- 今回のサンプルではトークンの有効期間を1時間とし、ブラウザのメモリに保持する。ページ再読み込み、ログアウト、認証切れの後は再ログインする。

| API                                                                    | 用途                                   |
| ---------------------------------------------------------------------- | -------------------------------------- |
| `GET /api/health`                                                      | DB 接続を含むヘルスチェック            |
| `POST /api/auth/register`、`POST /api/auth/login`                      | アカウント登録、ログインとトークン発行 |
| `GET /api/auth/me`                                                     | ログインユーザーの取得                 |
| `GET /api/items`、`POST /api/items`                                    | 一覧、作成                             |
| `GET /api/items/{id}`、`PUT /api/items/{id}`、`DELETE /api/items/{id}` | 詳細、更新、削除                       |
| `GET /api/openapi.json`、`GET /swagger-ui/`                            | API 仕様と操作画面                     |

## 4. 開発・検証・実行環境

- Node.js の版は `.node-version`、Rust と開発タスクは `mise.toml` で管理する。npm の設定はルートの `.npmrc` に置く。
- ルートで `mise run init` を実行して依存関係を取得し、`mise run dev` または `npm run dev` で Web と API を同時起動できるようにする。個別起動用の npm タスクも置く。
- ローカル開発では Web を `5173`、API を `3000` で起動する。Vite から `/api` と `/swagger-ui` を API にプロキシする。SQLite は既定でルートから起動したときに `app.db` を作成する。
- ローカルの起動設定を `.env.example` から作れるようにする。`JWT_SECRET` には十分な長さのランダムな値を使い、未設定・32バイト未満・サンプル値の場合は API を起動しない。
- TypeScript の型検査、oxlint と Clippy、Prettier と rustfmt、axum-test による統合テスト、本番ビルドをルートのコマンドから実行できるようにする。
- GitHub Actions の `.github/workflows/ci.yml` で、メインブランチへの push とプルリクエスト時に Web と API を別々のジョブで検査・ビルドする。成果物の配布や本番デプロイ（CD）は公開先を決めた段階で設計する。
- Dockerfile はマルチステージとし、Rust API と nginx で配信する Web の実行イメージを作る。Docker Compose で両方を起動し、Web は `8080`、API は `3000` でローカルに公開する。nginx で API をプロキシし、画面 URL への直接アクセスに対応する。SQLite は名前付きボリュームに保存する。

## 5. 作成完了の確認項目

- [ ] 初回セットアップから起動でき、追加の DB サーバーなしで SQLite の初期化まで完了する。
- [ ] 画面で登録・ログインし、アイテムの作成、詳細表示、編集、削除ができる。
- [ ] 統合テストで未認証、期限切れトークン、入力エラー、他ユーザーのデータの読み書き拒否を確認できる。
- [ ] ヘルスチェックと Swagger UI が開き、OpenAPI JSON を取得できる。
- [ ] 型検査、lint、整形チェック、テスト、本番ビルドが通る。GitHub に push したら Actions タブでも CI の結果を確認する。
- [ ] Docker を使う場合は Compose で起動でき、コンテナを作り直しても SQLite のデータが残る。

## 6. 別プロジェクトで決め直すこと

- サンプルの「アイテム」を対象業務のデータに置き換え、必要な画面、入力項目、権限を決める。
- 想定データ量や運用形態から、一覧のページ分割、DB の選択、バックアップと復元の手順を決める。
- 公開する場合は、HTTPS、ログイン試行の制限、メール確認、パスワード再設定、セッションの更新・失効のうち必要なものを決める。公開先に合わせてシークレットの管理と CD の手順を設計する。

このプロジェクトを起動する手順やコマンド一覧は [README.md](README.md) を参照。
